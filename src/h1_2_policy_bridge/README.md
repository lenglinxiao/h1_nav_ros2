# H1-2 policy bridge: isolated simulation only

This first phase is restricted to Unitree DDS domain 42 on loopback (`lo`), and accepts only simulator `mode_machine == 0` and `mode_pr == 0`. ROS requires `rmw_fastrtps_cpp` (selected by the launch and enforced by the node), and uses its own domain configuration; the Unitree domain parameter does not set ROS_DOMAIN_ID. The process never releases the original motion controller. Starting it does not publish motor commands. This software is not authorized for hardware.

The policy is `/home/llx/policy.onnx`, MD5 `b27c034920b671ffb33c920a58798d0a`. All policy parameters and static regression values are from the 2026-10-29 H1_2 ArmHold deployment guide supplied by the user. Original robot encoder offsets are retained. The guide calls wrist order pitch, roll while SDK/MJCF order is roll, pitch; the explicit name mapping implements that documented assumption, but the actual training order is unverified. Numerical regression cannot validate joint semantics.

Build after sourcing ROS Humble: `colcon build --packages-select h1_2_policy_bridge`. Run `colcon test --packages-select h1_2_policy_bridge` for core and model regression. Launch with `ros2 launch h1_2_policy_bridge policy_bridge.launch.py`; parameters are `model_path`, `cmd_vel_topic`, `network_interface`, `dds_domain`. Only `lo` and `42` are accepted. Start the simulator separately on the same loopback DDS domain.

The `~/passive`, `~/fix_stand`, `~/arm_hold_stand`, `~/arm_hold` Trigger services are manual. A fresh valid simulator state is required. Each stand transition takes at least 3 seconds; ArmHold additionally checks knee positions and upright orientation. These software checks do not establish the physical height or sling support described in the guide. A low-state or inference fault stops command publication and requires a new manual Passive request after state recovery. A velocity timeout of 0.4 seconds instead sends zero velocity while the policy maintains standing. The simulator uses explicit clipped torque with zero embedded kp/kd.

The public header `h1_2_policy_bridge/core.hpp` and library `h1_policy_core` expose policy-order state, observation, torque, ONNX inference and the manual controller for a simulation runner. The ONNX Runtime 1.22 directory and Unitree SDK root are CMake cache variables `ORT_ROOT` and `UNITREE_SDK2_ROOT`.

For the DDS smoke test, build with `BUILD_TESTING=ON` and run the node and `build/h1_2_policy_bridge/h1_policy_dds_smoke` on the same machine with `ROS_LOCALHOST_ONLY=1`, a ROS domain different from 42, and no physical robot connection. Call the node's Passive Trigger while the test publishes synthetic states; its `nonfinite` argument injects a non-finite joint state. The fake process checks startup silence, command CRC, finite torque and zero kp/kd, then verifies that fault stops publication. This test is separate from `colcon test` because DDS sockets require network permission and explicit loopback isolation. The node and SDK-only test use DT_RPATH for the SDK's matched CycloneDDS libraries; do not replace those with the ROS distribution's differently built libraries.

After building, run `bash src/h1_2_policy_bridge/test/run_dds_smoke.sh stale` and `bash src/h1_2_policy_bridge/test/run_dds_smoke.sh nonfinite` from the workspace root, with loopback socket access. Logs are in `/tmp/h1_policy_smoke/`. The script manages only its own two child processes.

The phase-1 node takes an advisory process lock for the current UID and loopback DDS domain 42. A second instance fails before DDS initialization; the OS releases the lock when the first process exits, even if the lock file remains. This protects against duplicate instances under the same UID; it is not a cross-user or hardware control-arbitration mechanism. Verify it with `bash src/h1_2_policy_bridge/test/run_lock_smoke.sh` from the workspace root when domain 42 is otherwise idle.
