# 会话交接

同一工作树中的模型或会话先读取 [SESSION.md](../SESSION.md) 的索引和当前任务文件；按需查看 [CONTEXT.MD](../CONTEXT.MD) 与专题文档，并只读检查工作区。跨会话或多步骤的新工作按 [任务模板](../tasks/README.md) 建文件；任务文件是状态事实源，索引只列入口。说“同步 session”更新任务与必要索引；说“继续任务 <ID>”先读取该任务，再结合最新指令决定下一步。

任务记录目标、范围、认领、依赖、进度、完成条件、验证和授权边界，日志只保留关键交接。并发认领和文件范围是协作约定，不是原子锁；冲突保留分歧并报告。记录的授权和现场状态有适用范围和时间，不能把历史动作自动当作新授权。切换分支或机器时需自行携带未提交文件；不自动 commit 或 push。

## 本问题记录

- 现象：换会话时需要快速找回具体任务，单一快照难以同时追踪多个任务。
- 已确认原因：原 `CONTEXT.MD` 主要是长期时间线，旧 `SESSION.md` 是单份当前快照；这不证明产品丢失聊天的原因。
- 实现：`SESSION.md` 作为短索引，`tasks/` 按任务保存状态和模板；`AGENTS.md` 约定读取、同步和并发边界，长期历史保留在 `CONTEXT.MD`。
- 验证：相对链接和模板必备字段检查无缺失，相关文件 diff 空白检查通过；未实际进行跨会话演练。没有自动 hook，执行依赖 agent 遵守约定，也不会自动迁移任务或重建进程。
